Phase 0: what the seams cost and save

Five extension seams landed in orlog core (ORLOG-SPEC.md §B12). These are the measurements: what one answer costs an agent in context, and what the read path costs at scale, before and after.

ScriptedDeriver, hashing embedder, exact-key queries — no API calls, no model download, nothing probabilistic. Token counts are chars ÷ 3.5. Python 3.12, Linux.

Read latency, before and after

p50 on a 2,500-event workspace, 30 runs per call. Before Phase 0 every one of these read and re-parsed the whole log; they read an index now.

before after

recall is the one that did not go flat. The projection cache is fully effective — a cached view costs nothing measurable — but two O(n) passes remain per call: re-materializing every fact from the index (22.5 ms) and rebuilding the verifier's ground-truth table (15.3 ms), 38 of its 42 ms.

Ingest throughput

Writes per second as the workspace grows. Before, three separate per-write costs each scanned the whole log, so throughput fell away as the log filled.
